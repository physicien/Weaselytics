# Pinned to a commit, NOT to `@development`: that branch moves, and the
# `lam_0/1/2` defaults of `beads` changed on it from 1.0 to None in
# commit 1ded189, which auto-scales each as
# `alpha / ||diff(y, d)||_1` — alpha over the L1 norm of the d'th
# finite difference of the data. CHANGELOG.rst stops at 1.2.1 and has
# no 1.3.0 section, so the only record is a `versionchanged` directive
# in the docstring. `_custom_beads` never passes them, so the effective
# regularization — and therefore every baseline, autocorrelation curve
# and selected `fcut` — would depend on the install date. Measured on a
# reference blank: baselines differ by up to 0.7% of the signal range,
# and r2 by 0.885 vs 0.950 at the same cutoff.
#
# Pin FORWARD, never back: the new auto-scaled default is the L1-norm
# scaling recommended by Ning et al. (2014) and used explicitly in the
# upstream `plot_beads_param_selection.py` example
# (`lam_0 = 1 / abs(y_transf).sum()`, etc.). The old `lam=1.0` is the
# unjustified value. Unpinning to an older pybaselines would be a
# regression, not a fix.
